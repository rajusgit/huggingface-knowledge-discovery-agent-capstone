# Hugging Face Knowledge & Discovery Agent

A chat-and-discovery copilot for AI/ML engineers: **Learn → Discover → Compare → Evaluate**.

- **Learn** – cited answers from 152 license-checked Hugging Face docs pages (Transformers, Datasets, Sentence Transformers, huggingface_hub, Hub), retrieved from Postgres + pgvector.
- **Discover** – live model/dataset search and details through FastMCP tools over the Hub API.
- **Compare** – side-by-side facts with missing-field warnings and constraint checks (license, size, language, task).
- **Evaluate** – small, reproducible embedding benchmarks in a sandboxed subprocess, **only after explicit human approval**.

Specs: [`specs/`](specs/). Plan and task log: [`tasks/`](tasks/). Results: [`observability/reports/`](observability/reports/).

## How it fits together

```
React (ui/) ──SSE──> FastAPI (src/api.py) ──> LangGraph agent (agents/graph.py)
                                               guard_input → classify_intent ─┬─ retrieve_docs (src/retrieval.py) ─┐
                                                                              ├─ call_mcp_tools (tools/mcp_server.py, stdio)
                                                                              └─ plan → human approval → benchmark ─┴─> synthesize → verify_citations
Postgres/pgvector, schema hf_discovery (RDS)        every LLM call goes through src/llm.py → OpenRouter
```

| Path | What lives there |
|---|---|
| `src/` | config, db, embeddings, **`llm.py` (the only LLM client)**, ingestion, chunking, retrieval, rerank, API, auth |
| `agents/` | LangGraph graph, Semantic Router, input/output guards, MCP tool loading + vetting |
| `tools/` | FastMCP server, Hub REST client, compare, sandboxed benchmark runner |
| `observability/` | golden set, 16-variant experiment, agent eval, red-team harness, tracing, reports |
| `standalone-scripts/` | CLIs: ingest, ask, agent chat, evals, red-team, registry builder |
| `ui/` | React + TypeScript + Tailwind (Vite) |
| `config/` | `config.yaml` (every tunable), `sources.yaml` (corpus registry), route/guard examples |

## Setup

Requirements: Python ≥ 3.11 and [uv](https://docs.astral.sh/uv/), Node ≥ 20, access to the Postgres instance (pgvector installed).

```bash
cp .env.example .env        # fill in: OPENROUTER_API_KEY, TICKERPULSE_DB_PASSWORD (+ optional HF_TOKEN, LANGSMITH_API_KEY)
uv sync
(cd ui && npm ci)
uv run python -m src.db --init          # creates schema hf_discovery (idempotent)
```

Secrets live **only** in `.env`. Everything else (models, thresholds, retries, timeouts, limits) is in `config/config.yaml`.

### Load the corpus

```bash
uv run python standalone-scripts/ingest.py --all                      # default chunker; validates, then publishes
uv run python standalone-scripts/ingest.py --all --strategy fixed50   # A/B chunkers are validated but not published
```

`config/sources.yaml` is generated by `standalone-scripts/build_registry.py` from `config/corpus.yaml`. Re-running ingestion on an unchanged corpus writes nothing; unchanged chunks reuse their embeddings.

## Run

```bash
uv run python -m src.main            # API on http://127.0.0.1:8000 (spawns the MCP server itself)
cd ui && npm run dev                 # UI on http://localhost:5173
uv run python standalone-scripts/ask.py "How do I limit generated length?"    # RAG from the terminal
uv run python standalone-scripts/agent_cli.py                                 # full agent, questions from stdin
```

Memory is **off** by default (UI checkbox); an approval prompt appears before any benchmark runs.

## Test

```bash
uv run pytest                    # ~300 tests; DB-backed ones need the RDS password
NO_DB_TESTS=1 uv run pytest      # what CI runs: no database, no secrets
RUN_LIVE_LLM=1 uv run pytest -k live   # opt-in live checks (small OpenRouter spend)
uv run ruff check .
(cd ui && npm test && npm run build)
```

## Evaluate and red-team

```bash
uv run python standalone-scripts/run_evals.py           # 16 variants: 4 chunkers x dense/hybrid x rerank on/off
uv run python standalone-scripts/run_agent_evals.py     # routing, tool use, approval gating, refusals, latency
uv run python standalone-scripts/run_redteam.py         # guards, tool escalation, indirect injection, access control
uv run python standalone-scripts/upload_golden.py       # to LangSmith (needs LANGSMITH_API_KEY)
```

Reports: [`final.md`](observability/reports/final.md) summarises everything against the spec's acceptance criteria.

## Safety design (all hand-built; every LLM call goes through `src/llm.py`)

1. **Input**: PII/secret masking (before the graph, because LangGraph checkpoints its input) → semantic guard → LLM self-check.
2. **Retrieval**: access filter (`public` only), PII redaction, retrieved text fenced as untrusted data, LLM screen drops passages carrying instructions.
3. **Tools**: allowlist from config, tool descriptions vetted at load, benchmark tool never exposed to the model, human approval via LangGraph `interrupt()`.
4. **Output**: streaming guard holds back a short tail so a leaked secret or system-prompt fragment is stopped before release.
5. **UI**: text rendering only (no `innerHTML`), http(s)-only links.

## Deploying to Railway

Not done from this repository's tooling; steps for the account owner:

1. Create a Railway project from this repo (no Dockerfile; `railway.json` sets the start command and `/healthz` check).
2. Service variables (never commit these): `OPENROUTER_API_KEY`, `TICKERPULSE_DB_PASSWORD`, `API_KEY` (a long random string), `API_AUTH_ENABLED=true`, `CORS_ORIGINS=https://<your-ui-domain>`, optional `HF_TOKEN`, `LANGSMITH_API_KEY`.
3. The API refuses to start if auth is on and `API_KEY` is missing. Check: `curl -i https://<api>/api/models/search` → 401; with `-H "X-API-Key: …"` → 200; `/healthz` → 200.
4. UI as a second service: `cd ui && npm ci && npm run build`, serve `ui/dist`; set `VITE_API_URL` and `VITE_API_KEY` **at build time**.
5. The RDS security group must allow Railway's outbound traffic (Railway egress IPs are not fixed).

**Know the limits:** a static key built into the UI bundle is readable by anyone who can open the UI, so it only keeps out callers who never loaded the UI. Put the UI behind its own access control, or move to per-user auth before exposing it publicly. The API also loads ~1 GB of ML models (MiniLM, cross-encoder, Docling is ingestion-only), so size the service accordingly.

## Known limitations

See [`observability/reports/final.md`](observability/reports/final.md): small held-out set, citation correctness below target, 8% upper bound on injection success, no LangSmith/Railway verification, intent routing at ~88%.
